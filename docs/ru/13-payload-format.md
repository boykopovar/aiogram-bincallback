# Формат payload на уровне бит

Итоговые байты перед `cipher.encrypt` и `wire_codec.encode` - непрерывный битовый поток без выравнивания между отдельными полями. Байтовое выравнивание применяется один раз, в конце, при переводе накопленных бит в `bytes`.

## Порядок байт

Все целые числа записываются и читаются как big-endian, побитово, через `BitWriter` / `BitReader` (`bitstream.py`). Запись - сдвиг аккумулятора влево на `bits` и добавление значения младшими битами. Чтение - извлечение `bits` бит с текущей позиции, считая от начала потока.

## Заголовок

Первые `HEADER_BITS = 24` бита payload:

| Поле      | Позиция (биты от начала) | Ширина             |
|-----------|--------------------------|--------------------|
| `prefix`  | 0..15                    | `PREFIX_BITS = 16` |
| `version` | 16..23                   | `VERSION_BITS = 8` |

Оба поля - unsigned. Кодируются `encode_header`, декодируются `decode_header`, не зависят от плана конкретного класса.

## Тело: порядок полей

После заголовка поля идут в порядке объявления в классе (порядок `CodecPlan`, построенного по аннотациям pydantic-модели). Порядок не сортируется по имени и не зависит от `default`/`default_factory`.

## Кодирование по типам

| Тип              | Что записывается на провод                                                           |
|------------------|--------------------------------------------------------------------------------------|
| `bool`           | 1 бит: `int(value)`                                                                  |
| `int`            | `bits` бит, `write_uint` (unsigned) или `write_int` (signed, дополнительный код)     |
| `Enum`           | `bits` бит, unsigned: `bin_order.index(value)`                                       |
| `List[Enum]`     | `len_bits` бит длины (unsigned), затем `item_bits` бит на каждый элемент по порядку  |
| вложенная модель | поля вложенной модели продолжают тот же поток, без заголовка и без выравнивания      |
| `Optional[T]`    | 1 бит присутствия перед данными; при `0` данные `T` полностью отсутствуют на проводе |

## Знаковые целые

`signed=True` использует дополнительный код (`_signed_to_unsigned` / `_unsigned_to_signed`) в границах ширины `bits`: старший бит - знаковый. Значение `-1` при `bits=8` записывается как `0b11111111`.

## Хвостовое выравнивание

`BitWriter.to_bytes()` добавляет от 0 до 7 нулевых бит в конец потока, чтобы длина стала кратной 8, затем переводит в `bytes`. Эти нулевые биты не читаются при `decode_fields` - позиция чтения (`reader.position_bits`) останавливается на последнем реально записанном бите последнего поля.

## Пример компоновки

Класс с `prefix=1, version=1` и полями `flag: bool`, `value: int = bfield(bits=8, signed=False)`:

```
биты 0..15   - prefix (16 бит)
биты 16..23  - version (8 бит)
бит  24      - flag (1 бит)
биты 25..32  - value (8 бит)
биты 33..39  - нулевое выравнивание до границы байта
```
